# 内容生产中心统一运营 PRD v2

## 1. 产品定位

内容生产中心是“市场资料—内容生产—经营反馈”之间的统一编排层。它不复制 OpenClaw 原始资料、不替代 Obsidian 正文、不伪造平台发布事实，也不把反馈分析拆成独立工作台。

日常用户只从首页进入，系统自动把已有对象汇总成下一步；详情页只在需要证据、人工判断或异常处理时打开。

## 2. 端到端主流程

```text
OpenClaw 资料监听
  → Topic 选题池
  → AI 评分（无凭证时由 Agent/API 补交）
  → 选题确认 / 自主派单
  → ProductionTask 与任务契约
  → Agent 执行并回传 Obsidian 产物
  → 人工最终发布
  → OPC-ERP 只读回流
  → 发布观察中的自动表现提示
  → 复盘案例 / 再分发任务 / 方法候选
  → 下一轮评分与任务契约读取历史表现和方法
```

## 3. 现有对象和状态

| 对象 | 归属 | 状态/用途 |
| --- | --- | --- |
| Topic | 内容中心 | `new → scoring → scored → selected`，另有 `expired/abandoned` |
| ProductionTask | 内容中心 | `queued → claimed → running → draft_ready/publish_ready`，另有 `blocked/failed` |
| TaskRun | 内容中心 | 每次领取、执行、重试和回传的不可覆盖事实 |
| PublicationObservation | ERP 回流 | `observed → matched → review_candidate`，引用外部 publication id |
| FeedbackSignal | 派生分析 | 由发布观察和规则计算，只在发布观察区域展示 |
| ReviewCase/MethodCandidate | 学习沉淀 | 人与 AI 复盘，方法升格前不改正式 Skill |

## 4. 自动化边界

系统自动做：

- 监听 OpenClaw 新资料、哈希去重和解析入池；
- 有 LLM 凭证时后台补齐待评分选题；
- 自主模式每 30 分钟按评分派发不超过日限额的任务；
- 生成任务契约、采集 Skill 哈希、校验回传产物；
- 每小时从 OPC-ERP 幂等同步发布观察并计算表现提示；
- 在下一轮评分中提供专业画像、覆盖记录和历史表现参考。

### 4.1 执行器桥接

生产任务不再依赖执行器自己扫描目录或猜测下一步。OpenClaw/Codex 通过 `POST /api/production/tasks/claim-next` 原子领取队列中的一条任务，服务端返回契约文本、任务 ID、运行 ID 和回传凭证；执行器随后调用 `start`，完成内容创作工作流后调用 `callback`。领取过程使用 SQLite 写事务和状态条件，避免两个执行器重复领取同一任务。

这只是现有 ProductionTask 的消费入口，不新增用户页面、反馈对象或第二套任务状态。若契约文件被移动或删除，服务端会尝试按当前 Skill 快照重建；仍无法恢复时任务不领取并返回明确错误。

### 4.2 资料异常可见

OpenClaw 文件读取失败、Markdown 解析失败和暂不支持的格式会先登记为未处理来源，再写入 `source_issues`。这类记录不伪装成已处理，也不丢失在进程日志中，后续可按来源路径重试。

人保留：

- 需要承担个人观点的选题取舍；
- 平台发布前的最终确认；
- 是否把复盘方法写入正式 Skill。

## 5. 首页信息架构

```text
首页：今日运营
├─ 流水线计数：待处理 / 已评分 / 生产中 / 待发布 / 已回流 / 待复盘
├─ 接下来：一个最高优先级动作和直接入口
├─ 系统依赖：资料监听、调度、AI、ERP、Obsidian 的真实状态
└─ 选题池：现有搜索、筛选、批量确认和详情
```

生产任务页保留任务队列和 ERP 发布观察；自动表现提示嵌在发布观察区域。复盘页只承载已经选择进入复盘的案例，不承担日常运营总览。

## 6. 复杂度控制

- 不新增独立“反馈决策工作台”；
- 不复制 ERP 指标，不把分析结果伪装成事实；
- 不引入云队列、多租户或复杂权限；
- 所有自动化周期必须幂等、可降级、可从日志定位；
- 外部平台自动发布另行评估，当前不绕过人工最终发布边界。

## 7. 验收标准

1. 打开首页能看到全流程计数、系统依赖和唯一下一步。
2. 新资料可自动进入选题池；配置 LLM 后后台能补齐评分，配置自主模式后能自动派发任务。
3. 任务契约和回传仍保留 Obsidian 产物校验，`publish_ready` 不等于已发布。
4. ERP 同步按外部 publication id 幂等，表现提示只出现在发布观察区域；提示不自动计入待复盘，只有明确创建的 ReviewCase 才进入复盘队列。
5. 复盘和方法沉淀可追溯，但不会未经确认修改正式 Skill。
6. 配置缺失、外部接口失败、重复执行和重启都显示真实状态，不阻塞首页和历史数据查看。
