# 内容生产中心升级 PRD：内容决策反馈层 v1

## 1. 背景与目标

OPC-ERP 是公众号、B 站等平台发布事实、指标、收入、KR 与 PDCA 的唯一事实源。内容生产中心负责选题、创作编排和复盘学习。本期不复制 ERP 原始指标，而是增加一层派生决策信号，把发布表现转成下一轮内容生产可执行的建议。

本期目标：

1. 通过一次操作或定时任务从 OPC-ERP 幂等同步发布观察；
2. 对已同步观察计算高传播、低传播、高互动、趋势下降和再分发候选等信号；
3. 让用户在现有生产任务页面查看证据、接受、忽略或进入复盘；
4. 为后续自动选题和 AI 内容编排保留结构化入口；
5. ERP 指标、原始数据和历史快照不被内容中心覆盖。

## 2. 范围

### 本期实现

- `feedback_signals` 派生信号表及无损迁移；
- ERP 内容表现同步后的规则计算；
- 信号队列 API：筛选、分页、汇总、重算、处理；
- 信号进入现有 `review_cases` 的动作；
- 决策反馈工作台；
- 每小时后台同步（未配置 ERP 时自动降级）；
- 幂等、日志、异常和测试。

### 本期不实现

- 自动覆盖或修正 OPC-ERP 指标；
- 自动修改正式 SKILL.md；
- 自动发布公众号文章；
- 模糊标题自动关联选题；
- 以 LLM 代替确定性指标计算；
- 新增多租户、复杂权限和云端部署。

## 3. 数据边界

```text
OPC-ERP
  发布事实、指标快照、收入、KR、PDCA
        │ 只读同步
        ▼
内容生产中心
  PublicationObservation（引用观察）
        ▼
FeedbackSignal（派生判断）
        ▼
复盘候选 / 再分发建议 / 后续选题参考
```

`feedback_signals` 不保存完整指标副本，只保存 observation 引用、信号类型、规则版本、证据摘要和建议动作。原始指标仍以 ERP 为准。

## 4. 信号规则 v1

规则使用同平台、同时间窗口内的已同步观察作为基线。当前窗口不足时只生成“证据不足”之外的可确认信号，不强行判断。

- `high_reach`：主要触达指标位于同平台近期高位，建议追写或再分发；
- `low_reach`：主要触达指标位于同平台近期低位，建议复盘标题、选题和分发时机；
- `high_engagement`：互动率位于同平台近期高位，建议提炼互动触发点；
- `declining`：ERP 提供的阅读/播放变化字段为负，建议判断热度衰退或内容承接；
- `repurpose_candidate`：高触达或高互动内容，建议改编到其他平台。

规则结果是经营建议，不是事实结论；每条信号必须带证据字段和规则版本。

## 5. 状态与操作

```text
open → accepted
open → dismissed
open → accepted（同时创建复盘案例）
```

关闭信号不删除数据。重算只补齐缺失或更新同一规则版本的开放信号，不恢复用户已处理的信号。

## 6. 界面原则

反馈层不设置独立导航或独立工作台。它嵌入“生产任务 → OPC-ERP 发布观察”区域，只显示当前最重要的少量信号；完整历史通过 API 和现有复盘页处理。这样用户不需要在任务、发布观察和反馈三个页面之间来回切换。

## 7. 验收标准

- 同一 ERP 发布观察重复同步不产生重复 observation 或 signal；
- 指标缺失、非数字或负值不会生成高低表现误判；
- 反馈工作台显示来源文章、平台、发布时间、证据和建议动作；
- 信号可按状态、平台、类型筛选并分页；
- 接受、忽略、创建复盘后刷新页面状态仍保持；
- ERP 不可用时保留已有观察和信号，页面显示同步错误；
- 定时任务不阻塞启动和首页；
- 全量测试通过。
