# 内容运营平台协作边界

## 一条主线

```text
OpenClaw 抓材料/抓平台数据
        ↓ 文件监听与 OPC-ERP 导入
OPC-ERP（发布、指标、收入、O/KR/PDCA 事实源）
        ↓ 只读内容表现 API
内容生产中心 8774（选题、任务契约、阶段状态、审计）
        ↓ 30 分钟脚本唤醒
Codex 运营主 Agent（运营判断、评分、派单、原生 Multi-Agent 创作）
        ↓
主编策划 → 作者研究与写作 → 编辑多平台/标题/视觉 → 主编终审
        ↓
8774 回传 publish_ready → 通知用户人工发布
        ↓
OpenClaw 抓取发布后的平台数据 → OPC-ERP → 下一轮反馈
```

## 职责边界

- OpenClaw：抓取公众号、B 站和热点材料，写入原始目录；不评分、不派单、不写稿。
- OPC-ERP：保存平台发布、指标、收入、O/KR/PDCA 和人工修正，是经营事实源；不内置 AI 判断。
- 内容生产中心 `8774`：管理选题、任务契约、内容产物指针、阶段状态和反馈信号；不覆盖 ERP 原始指标。
- Codex：通过 8774 读取上下文并写入受控的运营计划、评分、任务阶段和发布准备回传；不直接改 SQLite。
- 人：确认经营目标、审阅最终稿并点击各平台发布按钮。

## 调度规则

- `07:50` Codex：挖掘前一天真实工作，形成可追溯候选并同步到 8774。
- 每 `30` 分钟：8774 内部脚本只唤醒一次 Codex 运营器；Codex 读取每小时同步后的反馈，完成运营计划、评分、派单和创作，不重复触发 ERP 同步。
- `08:20` Codex：做当天运营总检，读取 8774 和 OPC-ERP 的待办、阻塞、待发布和数据回流，不另起固定创作线程，避免与 30 分钟唤醒器重复生产。
- 每 `1` 小时：8774 只读同步 OPC-ERP 发布表现，生成派生反馈信号。

## 故障降级

- OPC-ERP `8788` 不可用：8774 保留已有任务和创作能力，但标记“经营反馈不可用”，Codex 不得声称已完成数据回流。
- 8774 不可用：Codex 只保存运行报告和待同步候选，不得伪造任务创建或阶段完成。
- Codex 或 imagegen 不可用：任务回传 `blocked` / `failed`，保留中间文件和日志，不使用占位图放行。
- 只有主编终审通过且 8774 回传 `publish_ready` 后，才通知用户人工发布。
