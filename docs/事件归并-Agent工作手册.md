# 事件归类与归并 · Agent 工作手册

> 最后更新：2026-10-03（v7：merge 接口落完 key 后**整线统一**分类/地域/主体，
> `app/services/event_lines.py`；并标注"拆线不还原"缺陷。v6：归类树改成"每级都能看主题"
> +地域固定序+主体首字母序；日记类地域固定中国、三级主体 = 产出它的 Agent）

## 一、这个平台现在怎么归类

一条素材在平台里有**三个坐标 + 一个事件号**：

| 层 | 字段 | 取值 | 谁来定 |
| --- | --- | --- | --- |
| 一级 | `category` | 固定 9 类（见 `app/taxonomy.py`） | 8 类由**动词/动名词**决定；第 9 类由**来源目录**决定 |
| 二级 | `region` | 中国 / 美国 / 其他 | `app/geo.py` 规则，Agent 可修正；**日记类固定中国** |
| 三级 | `entity` | 政府机构名 / 公司名 / Agent 名（如 `OpenAI`、`SEC`、`网信办`、`Codex`） | 同上；**日记类 = 产出这条记录的 Agent** |
| 事件号 | `event_key` | 形如 `evt-1234`，同一件事的多条素材共享 | **Agent 判定**同一件事后写回 |

浏览入口是 `/tree`（左侧菜单「归类」）：分类 → 地域 → 主体。

**展示规则（2026-10-03 定，见 `app/ordering.py`）**：

- **每一级都能看到对应范围的主题**：选了分类就出该分类的**全部**素材，再选地域/主体只是往里收窄 ——
  不必一路点到第三级才有东西看。
- **二级地域顺序固定**：中国 → 美国 → 其他。**不按条数排**（按条数排会随数据变动换位，找东西时位置不固定）。
- **三级主体按首字母排**：英文按字母、中文按拼音首字母（同首字母内按拼音/字母序），
  分组显示 A/B/C… 表头。零依赖实现（GB2312 一级汉字区边界表），不引 pypinyin。
- 同一个格子里：同一件事的历次报道聚成一条线，按时间挂在同一条竖轴上。

## 二、分类由动词决定（最重要的一条）

**不看"谁的事"，看"发生了什么事"。** 失控就是安全 —— 不管是大模型失控还是智能体失控。

- `OpenAI 智能体失控入侵第三方` → **AI 安全与风险**
- `OpenAI 叫停 GPT-6.1 训练` → **AI 安全与风险**（叫停是因为安全事件）
- `OpenAI 融资 300 亿美元` → **行业与商业**
- `OpenAI 发布 GPT-5.6 模型` → **大模型与技术**
- `SEC 调查 OpenAI` → **政策与监管**（监管动作优先于安全动作）

判定顺序（`app/verbs.py`，高优先级命中即定）：
**政策与监管 > AI 安全与风险 > 行业与商业 > Agent 与智能体 > 大模型与技术 > AI 工具与应用**。

三条补充规则（v4 加）：

- **「行业讨论」是收容所，排最后**：没有单一主体的观点/评论/圆桌/盘点/趋势综述，
  动词和领域词全不命中时归此类（此前一律落"未识别"，翻不到）。它**不抢具体新闻**。
- **泛链只在标题生效**：`AI 工具与应用`/`大模型与技术` 的词太泛（发布/上线/工具/模型），
  靠**摘要**判定会误伤，所以摘要兜底只给 政策/安全/商业/Agent 四条链。
- **政府主体兜底到政策**：主体是政府机构时，即使没有政策动词也归政策
  （"特朗普新设超级智能部"是政治动作，不是行业闲聊）。
- **「周老师AI日记」按来源判，不按内容判**（第 9 类，2026-10-03 加）：
  `source_ref` 落在 `…\XX昨日工作挖掘\` 目录就给这一类，**排在所有内容判定之前**。
  理由：这批素材是周老师让 Agent 做的每日工作挖掘（记录他当天在自己系统里踩的坑、修的问题），
  跟外部 AI 新闻是两种东西；用关键词猜必然张冠李戴。
  判据只认目录名（`昨日工作挖掘`），不认 "Codex" 这个词 ——
  OpenClaw 抓的 `2026-06-08-openai-codex-chatgpt.md` 含 "Codex" 但**不是**日记。
  标记写成 `昨日工作挖掘` 而不是 `Codex昨日工作挖掘`：将来换 WorkBuddy 做每日挖掘时，
  `WorkBuddy昨日工作挖掘\` 目录**自动**归进来，不用回来改代码。
  **它不占 `CLASSIFY_VERSION`**（走版本号会触发全库重判、连带动到无关素材），
  改它只动 `app/taxonomy.py` 的 `DIARY_SOURCE_MARKER` + 启动"来源归口闸"。

- **日记类的二级/三级不走新闻口径**（2026-10-03 追加）：
  地域固定 `中国`（他写的），三级主体 = **产出这条记录的 Agent**
  （`Codex` / `WorkBuddy` / …，从来源路径的目录名里取，见 `taxonomy.diary_agent()`）。
  即「主体」对日记类不是"新闻里那家公司"，而是"谁干的活"。
  **反着判一次**：日记命中时**绝不调用** `judge()` —— 否则"日记里提到 OpenAI"
  会被塞进「美国 / OpenAI」格子，跟外部新闻混在一起（`app/geo.py::resolve_geo` 保证这点）。

**默认不跨分类**：一条事件线整线只有一个分类/地域/主体，实现见
`app/services/event_lines.py::unify_line()`（merge 接口调用它，2026-10-03 起）。
所以并线时**不需要**为每条素材单独纠结分类 —— 你只要判「是不是同一件事」。

## 三、你的工作：判"是不是同一件事"

平台只做粗筛（按共享实体词摆候选），**是否同一件事由你判定**。

接口：

| 用途 | 接口 |
| --- | --- |
| 候选组（粗筛，不是结论） | `GET /api/events/candidates?days=7` |
| 已归并的事件线 | `GET /api/events/threads` |
| 归并写回 | `POST /api/events/merge` `{topic_ids, event_key?, note, agent}` |
| 拆线（判错了退回） | `POST /api/events/unmerge` `{topic_ids, reason, agent}` |
| 归类树数据 | `GET /api/tree?period=7d&cat=&region=&entity=` |

`merge` 不传 `event_key` 时用最小 id 生成稳定 key（`evt-<id>`），重复调用幂等。

`merge` 落完 `event_key` 后会**整线一致**（2026-10-03 修，见下）：
分类 = 整线标题拼起来按动词再判一次；地域/主体 = 线内**最早一条**。
所以并线时**不需要**为每条素材单独纠结分类/地域/主体。

> ⚠️ **拆线不还原**（已知缺陷）：`unmerge` 只清 `event_key`，**不还原**被整线统一改过的
> 分类/地域/主体。先并后拆会把成员的原值丢掉 —— 需要回滚就从当次备份逐行还原。

**判定规矩**：

1. **错并比漏并糟**。说不出"同一个发生了什么"的，不要并。
   - 例：DevDay 上 Dots / Sol / Office / 插件 / Codex 云各自独立发布 → **不并成"一条 DevDay"**。
   - 例：OpenAI 入侵加拿大 / 联合国 / Hugging Face 三个不同目标 → **不并**。
2. **是进展就并入老线**。同一件事的后续报道、辟谣、二次发酵，并进已有的 `event_key`。
3. **候选里已归并的成员带 `event_key`**，那是用来判断"新出现的这条要不要并入那条老线"的。
4. **候选只抽英文实体词**，纯中文题材（如"快手调整 AI 组织架构""中国扩大 AI 高管出境限制"）
   **不会进候选**。这类请自行扫 `GET /api/topics?limit=200` 判断。

## 四、人可以手动归并

`/tree` 页面里勾选 ≥2 条素材 → 「归为同一件事」；每条线右侧有「拆线」。
人不用等 Agent 也能并。人并的线同样会整线统一分类。

## 五、你还可以修正归类

自动判定拿不准的（主体显示「未识别」、地域明显不对、分类明显不对），
可以按实际情况写回（是否开放给 Agent 由周老师决定）：

- `GET /api/tree` 先看现在是什么
- 主体/地域/分类的修正接口见 `app/routers/topics.py`

## 六、已知边界

- 主体「未识别」约 20.5%（329/1604）—— 多为多家公司对比、纯中文观点/趋势类素材（本来就没有单一主体）。
  判定规则是"宁可漏、不可错"：认不准就判未识别，也不硬塞进某家公司的格子。
- 多个国家共同参与的事件（如中美对话）归入「其他」，不硬塞给某一国。
- **来源类（日记）的地域/主体不由内容决定**：全部落「中国」，主体是 Agent 名。
  所以日记类在树上只有"中国"一栏，这是**设计如此**，不是漏判。

## 七、词典与判定规则怎么维护（AI 代维护）

三个东西，改动都在 `app/geo.py`：

| 改什么 | 改哪儿 | 注意 |
|---|---|---|
| 新增公司/机构 | `COMPANY_REGION`、`GOV_REGION`（关键词 → 归属地） | 中英文两种写法都要加，否则中文标题认不出 |
| 新增人物 | `PERSON`（人名 → (地域, 其代表机构)） | 人物排在**公司之后**（"特斯拉 CEO 马斯克"不许被人物抢去 SpaceX）；政府人物排**政府之前**（总统/部长 → `美国政府`）。马斯克刻意不收（多重身份，硬映射会抢别家新闻）|
| 同主体的别称 | `ENTITY_ALIAS`（别称 → 规范名） | 不加会变成两个格子（`Google` 和 `谷歌`）；检测时两种写法都要留在上表里 |
| 产品名 → 公司 | `PRODUCT_ENTITY` | 需**全文佐证**才认，避免"三星 Galaxy"被误判成"银河通用" |
| 改了判定逻辑 | `JUDGE_VERSION` **+1** | 启动时比对版本号决定是否全库重判 |
| 改了**内容类**分类规则 | `CLASSIFY_VERSION` **+1**（`app/verbs.py`） | 同上机制 |
| 改了**来源类**判据（周老师AI日记） | 只改 `DIARY_SOURCE_MARKER`（`app/taxonomy.py`） | **不要**动 `CLASSIFY_VERSION` —— 来源判定走启动归口闸，见第二节 |

**改词典后必做三件事**（顺序别换）：

1. **先试算**：跑 `tmp/geo_v3_trial.py` 那类脚本，看全库会移动多少条、谁从"未识别"被救回来。改一个词全库位移，不看影响面就落库等于赌博。
2. **再迁移**：停服务 → 跑 `init_database()` → 看输出里的"重判 N 条 / 改动 M 条"。
3. **后复验**：`region`/`entity` 为空必须是 0；事件线不能跨格子（迁移会自动整线统一，看输出里的"统一 M 条"）。

**词边界坑**：短英文词（≤6 且全字母数字）必须带词边界，否则 `SEC` 会命中 `security`、`MIT` 会命中 `limit`。`_hits()` 已按此实现，加新短词时留意。

**别过度调分类（v4 留证）**：试过三种"再调一轮"的方案，全被否决——讨论信号优先于泛链会误伤真新闻，限制摘要触发又会甩进「其他」垃圾桶。**现状（宁可漏、不可错）是刻意选择，不要为了降"未识别率"再动。**

## 八、入库必须同轮写 region/entity（踩过一次的坑）

归类树按 `category → region → entity` 分格，`region` 为空的行**在树里根本看不见**。

入库路径有三条，彼此独立，各自一条 `INSERT`：

| 路径 | 文件 |
|---|---|
| 抓取（OpenClaw 文件） | `app/services/topic_parser.py` |
| 手动录入 | `app/routers/topics.py` |
| Codex 主编选题 | `app/services/operator_service.py` |

**任何一条漏了列，新素材就会悄悄消失**（2026-10-03 实际发生过：当天入库 11 条全看不见）。

两道防线：

- 入库处调 **`geo.resolve_geo(标题, 全文, 分类, 来源)`** 直接写（正常路径）。
  **必须走这个统一入口，不要直接调 `judge()`** —— 日记类的地域/主体由来源决定
  （中国 + Agent 名），直连 `judge()` 会被正文里的公司名覆盖掉。
  传参顺序：分类先算出来，再把它和 `source_ref` 一起传进 `resolve_geo`。
- `scripts/init_db.py` 启动时扫 `region`/`entity` 为空的行补齐（兜底，覆盖将来新增的入库路径）。

新增任何写 `topics` 表的代码，都要照这两条检查一遍。

**别把项目工作目录当新闻来源**：`scan_directory()` 跳过 `03-projects` 目录
（那是周老师的项目过程文件，不是外部新闻）。2026-10-03 实际发生过：`03-projects\02时事评论\`
下两条 DseWiki 文件被误抓进选题池（#1153/#1154），已删除并加闸。
删数据的规程见 `docs/变更记录-2026-10-03-归类树展示规则与日记归属.md`（备份 + 回滚 SQL + 反向自检）。

**同类坑（2026-10-03 又踩一次）：入库用的分类实现必须和重判是同一个。**
三条入库路径早年 import 的是 `app.taxonomy.classify`（名词弱信号，2 个参数），
而启动重判与脚本用的是 `app.verbs.classify`（动词优先，含来源判定）——
**同一套规则两份实现**，直接后果是：新素材入库时按旧规则分类，与重判结果对不上
（试算时发现 5 条此类存量不一致，例如标题含"签署"的政策素材被旧规则判对了、
新规则判成商业）。已统一为 `app.verbs.classify`。
加新入库路径时照 `tmp/repro_diary_ingest.py` 写判据：**同内容放两个不同来源目录，
两条路径都要给出预期分类**（含反向对照，否则证明不了来源判定真的生效）。
