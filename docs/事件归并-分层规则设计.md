# 事件归并 · 分层规则设计（草案，待周老师定）

> 2026-10-03 起草。基于近 14 天真实数据（289 条）试算得出，未改动任何数据。
> 结论先行：你说的"一级 = 美国 AI 安全，二级 = 政府 / 各公司"这套逻辑成立，且能推广到全部题材。

## 一、现在的问题（用你库里的真实数字说话）

现在的归并是**平铺一层**：一条线 = 一件具体事。结果是：

- 近 14 天 **289 条**素材里，**OpenAI 一家占 67 条**，散在 **7 个类别**里。
- "OpenAI 智能体失控 / 被监管"这一件事，拆成了 **16 条独立素材**（1461、1482、1493、1495、1500、1510、1513、1517、1530…），每条各占一行。
- 你扫一眼列表，看到的是 16 条不同的标题，**看不出"这一件事已经连烧两周"**。

这就是你说的"很多事件都是美国对 AI 安全问题的"——数据上是真的，只是**看不出来**。

## 二、你说的规则，抽象出来是什么

你的原话：**"一级事件美国 AI 安全，二级分到政府和各个公司"**。

抽象成两句话：

- **一级 = 这件事属于哪一块**（AI 安全 / 政策 / 技术 / 商业…，再加它是**哪个国家**的事）
- **二级 = 这是谁的事**（政府？哪家公司？）

这个逻辑能推广到所有题材——因为**任何一条素材都能回答这两个问题**。

## 三、三层模型

```
第一层  域（哪一块）        美国 · AI 安全
   │
第二层  主体（谁的事）      政府 ── FTC / 加州总检察长 / 白宫 / 国会
   │                        OpenAI ── 暂停训练 / 解雇研究员 / Agent 失控
   │                        Anthropic ── Claude 自主入侵 / Epic 漏洞
   │
第三层  事件线（具体哪件事）  ← 这是现在的 event_key，保留不动
```

**重要**：第三层（具体事件线）必须留着。因为同一个主体下会同时烧好几件事——OpenAI 这半个月同时有"暂停训练""解雇研究员""Agent 失控"三件不同的事，不能糊成一条。

## 五、地域怎么判（这是最容易出错的地方）

你只说了"美国 / 中国"，但库里已经出现"澳大利亚传唤 OpenAI""日本声优起诉 TikTok"这类——**得有条规矩**，否则会乱判。我定了 5 条，按优先级：

1. **监管 / 法律事件 → 按监管者所在地。**
   「澳大利亚参议院传唤 OpenAI」→ 归**澳大利亚 · 政策与监管**，不是美国。因为是澳洲在管。
2. **公司的事 → 按公司总部。**
   Anthropic = 美国，DeepSeek = 中国，Manus = 中国。
3. **政府的事 → 按那个政府。**
   白宫 = 美国，网信办 = 中国。
4. **多方博弈 → 「全球」或「中美」这种跨域标。**
   「中美达成 AI 安全对话机制」→ 归**全球 · 治理与竞争**，不硬塞给某一国。
5. **研究 / 报告 / 无主体 → 「全球」。**
   论文、行业调研，没有国别归属。

> 试算中发现 3 条会被规则误判，正好说明**纯规则不够，最后必须由 Agent（Codex）定稿** —— 这也正是现在"平台粗筛 + Agent 判定"架构的意义，只是把粗筛从"共享词"升级成"地域 + 主体"。

## 六、什么情况不并（延续"宁可不并"）

- **同一家公司 ≠ 同一件事**：OpenAI 暂停训练 与 OpenAI 改订阅价 → 两件事。
- **同一类别 ≠ 同一件事**：都属于"美国 · AI 安全"，但 FTC 调查和 Anthropic 漏洞是两件事。
- **同主体跨域不合并**：OpenAI 的安全事件留在"AI 安全"域，商业事件留在"商业"域 —— 各归各位，靠**主体视图**汇总（见下）。
- 不确定就不并。

## 八、意外发现：真正值钱的是"谁的事"这条轴

试算时算了一笔账：

```
OpenAI   横跨 7 个类别：AI安全 / 工具 / 智能体 / 技术 / 政策 / 商业 / 其他  → 67 条
Google   横跨 6 个类别                                                  → 19 条
Anthropic 横跨 6 个类别                                                 → 18 条
Meta     横跨 5 个类别                                                  → 16 条
```

**结论**：你要写"OpenAI 这轮到底怎么了"的时候，需要的是**按主体聚一次**，而不是按域看。所以除了你说的"域 → 主体"树，还应该有一个**主体视图**：

```
OpenAI（近 14 天 67 条）
├── 安全事件 (16)   暂停训练 / 解雇研究员 / Agent 失控 …
├── 商业与资本 (12)  300 亿融资 / 订阅改价 …
├── 模型与技术 (11)  GPT-6.1 Sol / Decisions API …
├── 智能体 (9)       DevDay Dots / Codex 云环境 …
└── …
```

**两条视图共用同一份数据，只是排序轴不同。** 这是这套规则最值钱的地方。

## 九、怎么落地（等你点头再动）

1. **每条素材多存两个信息**：`地域`、`主体`（+ 主体类型：政府/公司/机构/个人）。类别和事件线都不动。
2. **`/events` 页从平铺改成树**：左边域 → 右边主体 → 点开看具体事件线。
3. **加主体视图页**（或同一个页面切一个开关）。
4. **候选接口升级**：现在只按标题里的英文词分堆（中文标题根本不进候选），换成按"地域 + 主体"分堆，主体从一张**词典**里认（OpenAI / Anthropic / 白宫 / FTC / DeepSeek / 华为…）。
5. **存量 1591 条回填**：用今天的规则先跑一遍自动打标，再由 Agent（Codex）校正 —— 试算脚本已证明能自动打上约 8 成，剩下 2 成靠人工/Agent。
6. **词典由 AI 代维护**：出现新公司/新机构，AI 加一行，你不用管。
