# 变更记录 2026-10-03：素材使用状态 + 类别聚焦周期

## 一句话

选题的状态不再表达"流水线走到哪一步"，只表达一件事：**这条素材我用没用**；
类别聚焦新增统计周期（近7日 / 近30日 / 本季度 / 本年 / 历史全部）。

## 为什么改

周老师 2026-10-02 已定：这个平台只做选题供给（素材库），平台外才是写稿、发布、复盘。

- 旧状态 `new / scored / selected / abandoned / expired` 是给自动化流水线用的。
  素材不需要归档、不会自动过期，"已选中/已放弃"也不是他的话——那 27 条 `selected`
  是 Codex 自动任务挑的，不是他挑的。状态放在库里没有意义，还会和事实打架。
- 类别聚焦原来只显示"当天"或"全库"两个口径，切换不了周期。周老师的判断方式是
  "最近哪类事多"（例如最近 AI 安全的事特别多），这需要按周期看，不是按天也不是全库。

## 改了什么

### 1. 状态语义收敛（唯一事实来源 `app/statuses.py`）

| 旧状态 | 新状态 |
| --- | --- |
| `new` / `scored` / `selected` / `scoring` | `unused` 未用 |
| `abandoned` / `expired` | `dropped` 弃用 |

- 只有三种使用状态：`unused`（未用）/ `used`（已用）/ `dropped`（弃用）。
- "是否已评分"不再是状态，而是事实：`topic_scores` 里有没有记录。
  这样同一件事只有一份实现，不会出现状态和评分记录互相打架。
- 迁移写在 `scripts/init_db.py` 的启动迁移里，每次启动跑一遍，已收敛的行不再匹配，
  因此幂等；逐条写 `usage_status_migrated` 审计事件，可回溯。
- 本次实际迁移：1586 条（其中 `selected` 27 条 → 未用），审计事件 1586 条。

### 2. 状态写入点收敛

- 评分（`scoring_engine`）不再改选题状态；"待评分"改为按 `topic_scores` 有无记录判定。
- 建创作任务（`production_service.create_task`）不再把选题改成"已选中"，
  只补记 `selected_at` / `selected_note`；前提条件改为"这条素材已有评分"。
- OpenClaw 采集入库（`topic_parser`）、主编主动选题（`operator_service`）写入 `unused`。
- 平均分统计（`stats`）不再用 status 过滤。

### 3. 新增接口

- `POST /api/topics/{id}/usage`，body `{status, note}`：唯一能改使用状态的入口。
  非法值直接 400（如 `scored` 现在不是合法状态）。
- `POST /api/topics/batch-usage`，body `{topic_ids, status}`：批量标记，逐条返回，
  实际改了几条也一并返回。
- `GET /api/categories?period=7d|30d|quarter|year|all`：类别统计带周期，并附全库总数。
- `PUT /api/topics/{id}/status` 仍为 410（禁止直改状态）。

### 4. 界面

- 统计卡改为：素材总数 / 待评分 / 未用 / 已用 / 弃用。
- 分段筛选：全部 / 待评分 / 已评分 / 未用 / 已用 / 弃用。
- 每张卡片右侧：**"我用了"打钩**（勾上=已用，取消=未用）+ "不用了"（弃用）/ "收回"。
  批量浮条同口径：批量标记已用 / 恢复未用 / 批量弃用。
- 类别聚焦新增周期切换条；卡片大字=该周期条数，小字=已评分 / 最高分 / 全库总数；
  卡片下方写明周期区间与合计条数。
- **口径一致性**：类别卡片是按周期统计的，所以点进去的列表也切成同一周期
  （URL 带 `scope=period`），保证"卡片 29 条 = 明细 29 条"。平时浏览仍是左侧日期导航的单日视图。
- `apiPost` 失败不再静默：写操作失败会中文提示原因并中断，不会刷新成"好像成功了"。
