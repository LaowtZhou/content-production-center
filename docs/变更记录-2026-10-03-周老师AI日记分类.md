## 一、这类素材是什么，为什么不能靠内容猜

这批素材来自 `C:\AI_workspace\AI内容创作\02-topics\AI创作\Codex昨日工作挖掘\`
目录（每天一个 md），内容是**周老师自己当天在系统里踩的坑、修的问题**——
比如"一键启动脚本卡住""20 篇抓取上限卡住旧账号同步"。

它和外部 AI 新闻是两种东西：
- 外部新闻的主体是"某公司/某机构"；
- 这类素材的主体是"周老师自己的系统"。

用关键词判定必然张冠李戴（"导入成功却看不到数据"该判商业还是技术？都不是）。
**所以判据是来源路径，不是内容。** 来源是硬事实：同一个目录下的素材永远归它，
不随标题措辞漂移。

**只认目录名，不认 "Codex" 这个词**（加保护反着判）：OpenClaw 抓的
`2026-06-08-openai-codex-chatgpt.md`、`2026-07-01-03-OpenAI-Codex-Micro.md`
都含 "Codex"，但它们是外部新闻，**必须不判日记**。

## 三、为什么「周老师AI日记」不占 `CLASSIFY_VERSION`

第一版实现是给 `CLASSIFY_VERSION` 3 → 4，走全库重判。**试算直接否掉了这条路**：

跑全库试算时发现，除了 30 条日记素材归位，还会**连带改 5 条无关素材**：

| # | 原标题 | 库里现值 | 全库重判会变成 |
|---|---|---|---|
| 1466 | Meta makes the Muse filesystem even… | 大模型与技术 | 其他 |
| 1490 | Muse 能克服 Meta 的信任危机吗？ | Agent 与智能体 | 行业与商业 |
| 1526 | OpenAI DevDay 2026 今日开幕… | Agent 与智能体 | 行业讨论 |
| 1588 | 特朗普签署行政命令，联邦政府将使用"超级智能"取代"人工智能" | 政策与监管 | **行业与商业**（明显判错） |
| 1593 | OpenAI 解除三名安全研究员职务 | AI 安全与风险 | 政策与监管 |

这 5 条不是新类造成的，是**存量 category 与当前内容规则的既有不一致**，
被"全库重判"顺带引爆。为一件只为来源归口的事，去动 5 条内容判定（其中一条明确变差）
= 范围外副作用。

**来源判定与内容判定是两条链**：来源是硬事实、幂等、确定，不需要版本号；
内容规则变了才需要全库重判。所以拆成两条链，各自用合适的机制。
代价：`CLASSIFY_VERSION` 不动，那 5 条存量不一致**这次不修**（属于另一个问题，见第五节）。

## 四、中途发现的既有缺陷：入库与重判是两套实现

改 `topic_parser.py` 加第三个参数后，入库路径**必崩**：

```
TypeError: classify() takes from 1 to 2 positional arguments but 3 were given
```

查下去，根因不是参数写错，是**实现分叉**（`grep` 实证）：

| 用在哪 | import 的是 | 规则 |
|---|---|---|
| 三条入库路径（抓取 / 手动 / Codex 主编） | `app.taxonomy.classify` | 名词弱信号，2 参数 |
| 启动重判（`init_db.py`）、两个脚本 | `app.verbs.classify` | 动词优先，3 参数 |

也就是说：**新素材入库按旧规则分类，重启重判按新规则**，两者长期对不上。
这正是第三节那 5 条不一致的来源之一（例：#1588 的"联邦政府"命中旧规则的政策词 → 判政策；
新规则的"签署"命中商业链 → 判商业）。

这违反项目定的"同一套规则只允许有一份实现"。**已统一为 `app.verbs.classify`。**
副作用要说清：新素材入库的分类从此与重判规则一致，个别素材的入库判定结果会与以前不同。
