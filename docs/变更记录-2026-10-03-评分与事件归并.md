  本轮 116 条落在 **1.5—7.9、中位 6.8**（这几天正好是 OpenAI DevDay + 安全事件密集期，素材整体偏强）
- 每条都写了三维理由 + **一句可成文的判断句**（`key_angle`）
- 时间窗口窄（09-28~10-03），不涉及"预热后再发要降新颖度"的历史消耗

### 明确"不并"的（判断边界，供复核）

- **同一家公司但事件不同**：OpenAI 的"入侵加拿大政府网站 / 联合国网站 / Hugging Face"是三个不同目标，不并；
  "OpenAI 叫停模型" 与 "OpenAI 被 FTC 调查" 不并。
- **同一场 DevDay 的不同产品**：Dots / Sol / Office / 插件 / Codex 云环境 / Decisions API —— 各是独立产品发布，
  **没有并成"DevDay 一条线"**。只把 Dots 的"预告 + 发布"并了（那是同一个产品的同一次发布）。
  这是刻意的：手册要求同组能说出"同一个发生了什么"，这些产品说不到一起。
- **同词不同事**：`shared_token=jev` 下的 TypeSafe Jev / Cloudflare Cleft / OpenAI Decisions API 是三家竞品，不并。

### 顺手修的缺陷

跑完发现候选接口有个会咬人的地方：**已归并的条目还会继续出现在候选里**，
而 `merge` 是直接 `UPDATE event_key` —— Agent 下次如果照候选判，
可能把已经属于 `evt-1461` 的条目并进另一条线，**把原来那条线打断**。

已修 `app/routers/events.py`：**整组都已归并的候选不再摆出来**；
只要组里还剩未归并成员，就整组返回（已归并成员带 `event_key`），
这样 Agent 能判断"新出现的这条要不要并入那条老线"，又不会重复判断。
候选组数 46 → 39，实测"仍整组已归并"的组 = 0。
同步在 `docs/事件归并-Agent工作手册.md` 补了这一节，并写明候选的另一个边界（见下）。

## 三、已知边界（需要您定的）

**候选只按标题里的英文实体词分堆**（openai / anthropic / amd / manus …）。
**纯中文标题不会被分堆** —— 例如"快手调整 AI 组织架构""中国扩大 AI 高管出境限制"这类，
下次 Codex 只靠候选接口跑，会**漏掉中文题材的重复事件**。
本轮是我手动把 116 条读完了才补上的。要根治有两条路：
1. 给候选加中文实体抽取（要配停用词，否则"智能/人工"这类词会造一堆假候选）——**属算法级改动，等您点头**；
2. 手册里已经写明"中文题材请自行扫 `/api/topics` 判断"，靠 Codex 每次都全扫一遍。

**现在没有替您选**，选了再说。
