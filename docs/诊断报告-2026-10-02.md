### 那版到底哪里做得不好（我从代码里查出来的，不是猜）

你说 GLM 5.3 Flash 做得不好。我读了源码，**四个问题，其中两个是硬伤**：

1. **注释在说谎（硬伤）。** `event_threads.py` 第 71 行注释写"标题权重高于摘要：标题 bigram 计 2 份"，代码实际是 `(title | summary) | {u for u in title}`——集合的"自己并自己"等于自己，**去重后权重归零**。也就是说：写得像承诺的功能，根本没实现。
2. **召回率低到失去意义（硬伤）。** 阈值是"共享 bigram ≥ 8 且 Jaccard ≥ 0.25"，但只要标题里有共同的英文词（`openai`、`anthropic`），门槛就降到 0.12。结果是：**英文名重合就归并，中文措辞不同的同事件反而归不上**。实测 178 题只归并出 4 题（2.2%）。而中文媒体讲同一件事的标题措辞差异极大，纯 bigram 抓不住。
3. **弹药包被 Key 卡死，看起来永远零产出。** `ammo_service._maybe_extract()` 在 `llm_api_key` 为空时直接把状态写成 `pending_key`。你说 Key 只是兜底，那这个模块的"事实提取"就**永远不会有输出**——这是它"做得不好"的观感来源之一，其实是不该把兜底依赖当主路径。
4. **你要的两件事它都没做**：没有**类别**维度、没有**事件之间的关联引用**。它只做了"同事件归并"这一半。

**结论**：方向完全对（甚至覆盖了你现在的三件抱怨 + 顺手补了覆盖查重的洞），实现是"用规则硬抠"的一版，达不到能用的召回率。**这一块值得重建，但重建的路径不该是抠 bigram。**

## 四、题材供给本身的问题（在本分范围内，必须修）

### 4.1 信源等级字段已完全失控 ⭐ 最该先修

`topics.source_level` 在 1,580 条里跑出了 **130 多种自由文本值**：

```
二级原创(651)  P1 原创通讯社与媒体(205)  (空130)  一级官方(109)  三级聚合(101)
P2 专业媒体原创(72)  P0 官方(31)  P1(10)  P2 国内专业媒体原创(3)  …
二级原创（路透社独家报道） / 🥉 二次聚合（第三方研究，媒体转述） /
🥇 官方源/权威通讯社（路透社一手报道） / P2（官方公告为 P0，本文按公告日与媒体转载核实定级）
```

**后果**：按信源等级**筛选、排序、统计、聚合全部失效**。"一手信源还是二手转述"是新闻选题最要紧的一维，现在等于没有。

**这是"看起来像有、实际不能用"的数据**——比没有更危险，因为它会让人以为可以按等级挑题。

**修法**：收敛成 `P0 官方 / P1 原创通讯社与头部媒体 / P2 专业媒体原创 / P3 聚合或社交线索` 四档枚举；历史值按规则批量映射；原始描述保留到备注列不丢。

### 4.2 "这道题我写过没有"——系统答不出来

- `topics.coverage_status`：**1,580 条全部是 `not_checked`**
- `coverage_records`：**0 条**
- 评分 prompt 里"近期已覆盖的主题关键词"因此永远输出"暂无覆盖记录"；"新颖度"这一维的打分**没有事实依据**

已经发生实际重复：`Anthropic Claude Code 自动模式将默认开启，8月14日生效` 重复入库 **5 条**；`OpenAI 暂停 Astra 模型研发…` 重复 **4 条**（都是 08-10 那天）。同一天还有 4 组标题前 14 字相同。

### 4.3 高分题没有出口

- 456 条有效评分里，**7 分以上 665 条（45%）、8 分以上 292 条**
- 首页查询是 `ORDER BY news_date DESC, id DESC`（`app/main.py:227`）——**按日期排，不按分数排**
- 结果是：即便打了分，你打开首页看到的仍是"按天铺开的清单"，不是"今天建议写这 3 条"

**7 分以上占 45% 本身说明评分区分度不足**——一半都是高分，它就无法充当筛选器。你既然走 Agent 评分，这一条要靠**打分口径（拉开档位）** + **一个"今日推荐"出口**来解决，而不是改算法。

### 4.4 数据黑洞：有题你看不见

| 黑洞 | 数量 | 后果 |
|---|---|---|
| `news_date` 为空 | **65 条** | 按日看板**永远看不到** |
| `source_level` 为空/null | **195 条** | 无法分级 |
| `source_ref` 为空 | 23 条 | 追不回原始资料 |
| 源文件解析出 **0 条**选题 | **70 个** | 料进来了没变题 |
| 而 `source_issues` 只登记 | 16 条（open 仅 7） | **静默丢料，无人知道** |
| `topic_sources.availability_status = unknown` | **1,562 / 1,585** | AGENTS.md 声明了"可访问性异常"，实际**基本没校验过** |

### 4.5 表现信号从未回流

- `publication_observations` 306 条（微信 255 + B站 51），状态**全部 `observed`**——「已关联 / 待复盘」两级**一次没发生过**
- `feedback_signals` 459 条，状态**全部 `open`，处理 0 条**
- 也就是说：系统已经算出了"哪些题表现好、哪些在下滑"，但**这些结论从未影响过任何一次选题决策**

对"只做题材供给"来说，这一块**其实有用**（表现好的题 → 说明这类题材值得再挖），但它现在没有出口。要么给它一个出口，要么承认它是死重。
